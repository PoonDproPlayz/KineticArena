## Goal and user requirements

Build a 500 g combat robot practice simulator with MuJoCo physics. Import a Fusion 360 robot as individual bodies, retain the Fusion occurrence/folder tree and available material, appearance, and mass information, and let the user assign one or more bodies to a main frame, each wheel, or a weapon. For example, the weapon's frame, blades, and screws must share one rigid weapon assembly and one rotation axis. The user needs a manual weight for every part and editable physical settings.

The arena and fighting robot should remain the main 3D view. A floating CAD setup window contains both the assembly controls and a separate, selectable 3D robot preview. Users must select parts from that preview, choose an axis target from a weapon/wheel dropdown, click edges around a CAD hole, and fit an axis through its center. They also need to hide/show CAD bodies in the preview independently of whether those bodies are included in the physics model, plus orbit, tilt, pan, and zoom controls. A simple one-command setup and a separate everyday launcher are required.

## Current standalone implementation

- `Standalone/main.cpp` is a native C++ app using MuJoCo 3.3.7, its classic OpenGL renderer, SDL3, and Dear ImGui. Filament was discussed as the intended rendering upgrade, but is **not implemented** and requires a MuJoCo upgrade. Do not describe the current app as Filament based.
- The stock model is `Assets/CombatSim/Models/CombatRobot500g.xml`. It has a 0.0004 s (2,500 Hz) physics timestep, a 2 m arena, two practice robots, and a 30,000 RPM player weapon target. W/S drive, A/D turn, Space spins the weapon; a gamepad uses the left stick and left shoulder or south button. The GUI has pause/reset and drive settings.
- The arena occupies the main window background. The CAD setup is one floating window with the Fusion tree and controls beside a distinct 3D CAD preview; the main controls can hide/reopen it. The CAD preview uses its own fixed MuJoCo model, `combatsim_preview.xml`, while `combatsim_generated.xml` is the simulated assembly model.
- `Standalone/FusionBundle.cpp/.h` loads schema 2 Fusion bundles and older schema 1 bundles, checks all referenced STLs before import, and exposes the occurrence tree. Bodies and folders can be assigned to Main frame, wheel or weapon rigid assemblies, or Exclude. Multiple bodies can belong to one moving assembly; additional assemblies can be added.
- Per-body **Weight (g)** accepts a manual mass; **Use Fusion** restores the exported mass. The importer also exposes color and friction overrides and displays physical material data. `combatsim_setup.json` next to the manifest saves assignments, pivots, axes, overrides, and preview visibility. Saved masses use kg internally. Generated rigid-body inertias are approximate bounding-box inertias. Fusion material data is retained for review, but texture/elasticity data is not mapped to MuJoCo and contact friction is an editable estimate.
- The CAD preview supports part clicking, selection highlight, **Assign selected part**, **Deselect part**, part/folder visibility checkboxes and Show/Hide controls, plus **Show only selected**. Preview visibility is independent of physical inclusion and persists as `partOverrides.previewVisible`. Hidden parts are also filtered from picking. Left drag orbits/tilts, right drag pans, and scroll zooms; the canvas captures dragging so the floating window does not move. Reset view and a tilt control are available.
- The **Axis target (weapon / wheel)** dropdown above the 3D preview selects the exact moving assembly. **Select hole for chosen axis** starts rim selection. Click at least three STL boundary/crease edges in sequence, then **Fit axis through hole** fits a circle in the selected plane and uses its center and plane normal for the pivot/axis. A green chain previews the points; Undo point, Cancel axis, Flip axis, and manual XYZ edits are available. The clicked parts must belong to the selected assembly. This operates on tessellated STL feature edges and an approximate circle fit, not original Fusion B-Rep topology. Old Shift/Ctrl click instructions should not be presented as the current UI workflow.

## Export, run, and import

- Fusion exporter: `Fusion360Exporter/CombatSimExport.py` with `config.json`. In Fusion 360, open **Utilities > Add-ins > Scripts and Add-ins**, add the `Fusion360Exporter` folder, and run `CombatSimExport` on the open design. It writes `<design>_MuJoCo/manifest.json` and binary STLs in nested `Parts` folders matching occurrences. Schema 2 includes native transforms, per-body mass/density/material properties and available appearance color/roughness, while preserving fields used by the older Unity importer. A fallback B-Rep tessellation path handles cases where Fusion reports STL export success without writing a valid file; each STL is validated before its manifest entry is committed. Exporting all relevant bodies, including hidden ones, is part of the workflow; verify actual Fusion behavior if changing this.
- First-time Windows setup from repo root: `powershell -ExecutionPolicy Bypass -File .\Standalone\setup.ps1`. It installs missing Git, CMake, and Visual Studio 2022 C++ Build Tools with WinGet, downloads MuJoCo 3.3.7 into ignored `Standalone/.deps`, builds, and launches. Add `-NoRun` to build without launching. The earlier WinGet Build Tools spinner was a setup issue; the tools were subsequently installed and MSVC builds now pass. See `Standalone/README.md` for manual CMake setup.
- For normal launches, double-click `Run CombatSim.bat` at the repo root. It runs the existing Release executable with the stock MJCF; it does not repeat setup. In the app, use **Browse...** in CAD setup and select the bundle's `manifest.json`, assign assemblies and axes, then **Apply and preview**. **Resume** drives the compiled robot; **Save setup** writes the JSON beside the manifest.

It has 95 parts and its generated preview/simulation XML and `Parts` directory exist. An older bundle under a different user path had eight missing STLs; that is historical, not the current state.
